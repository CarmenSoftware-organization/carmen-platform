# ยืนยันอีเมลก่อนสร้างบัญชี — ส่วน platform

ดีไซน์ฉบับเต็มอยู่ที่ฝั่ง backend เพราะแกนของงานอยู่ที่นั่น:
`../../../carmen-turborepo-backend-v2/docs/superpowers/specs/2026-08-08-verify-before-register-design.md`
(ข้อ 10 คือส่วนที่ว่าด้วยคำเชิญทั้งหมด)

เอกสารนี้สรุปเฉพาะสิ่งที่เปลี่ยนในรีโปนี้

## ทำไมรีโปนี้ถึงเกี่ยว

เส้นทางสมัครกำลังกลับลำดับเป็น **ยืนยันอีเมล → สร้างบัญชี** ผลพลอยได้คือ token ของคำเชิญ ซึ่งถูกส่งไปยัง
อีเมลของผู้รับอยู่แล้ว **พิสูจน์ความเป็นเจ้าของอีเมลอย่างเดียวกับลิงก์ยืนยัน** ผู้ถูกเชิญที่ยังไม่มีบัญชี
จึงไม่ต้องไปสมัครแยกแล้วยืนยันอีเมลซ้ำอีกรอบ — ตั้งรหัสผ่านแล้วเข้าร่วมได้ในลิงก์ใบเดียว

## หน้ารับคำเชิญ — ของใหม่ทั้งหน้า

ตอนนี้ **ยังไม่มีหน้ารับคำเชิญอยู่ในรีโปใดเลย** มีแต่ฝั่ง Admin ที่ออก ยกเลิก และส่งซ้ำ
เพิ่ม public route `/invitations/:token` ใน `src/App.tsx` คู่กับ `/` และ `/login`

```
โหลด GET /api/invitations/:token
  ├─ 410 → "ลิงก์นี้ใช้ไม่ได้แล้ว" พร้อมทางออกไปหน้าแรก
  ├─ requires_signup = true
  │     → สรุปสิ่งที่ถูกเชิญ (เครือ · หน่วยธุรกิจ · บทบาท · วันหมดอายุ) + ป้ายอีเมลที่ mask ไว้
  │     → ฟอร์ม ชื่อ นามสกุล เบอร์ รหัสผ่าน ยืนยันรหัสผ่าน
  │     → POST /api/invitations/:token/accept-with-signup → 201 → ไป /login พร้อมข้อความสำเร็จ
  ├─ requires_signup = false และยังไม่ล็อกอิน
  │     → ปุ่ม "เข้าสู่ระบบเพื่อรับคำเชิญ" → /login?redirect=/invitations/:token
  ├─ requires_signup = false และล็อกอินด้วยอีเมลเดียวกับคำเชิญ
  │     → ปุ่มยินยอม / ปฏิเสธ ใช้ accept และ decline เดิม
  └─ ล็อกอินอยู่ด้วยอีเมลอื่น
        → "คำเชิญนี้ส่งถึงบัญชีอื่น" พร้อมปุ่มออกจากระบบแล้วลองใหม่
```

กรณีสุดท้ายสำคัญ — ไม่มีมันแล้วผู้ใช้ที่ล็อกอินค้างด้วยบัญชีอื่นจะกดยินยอมแล้วได้ 403 ดิบ ๆ
โดยไม่รู้ว่าต้องทำอะไรต่อ

หลังรับคำเชิญสำเร็จ ผู้ใช้จะไปทำงานจริงที่แอป inventory ไม่ใช่ที่ platform — บอกทางด้วยข้อความ
ไม่ใช่ redirect ข้ามแอปเงียบ ๆ

## หน้าจอ Admin ที่ต้องปรับ

| ไฟล์ | สิ่งที่เปลี่ยน |
|---|---|
| `src/pages/clusterAdmin/InviteUserDialog.tsx` | `DialogDescription` บอกได้แล้วว่าผู้รับไม่จำเป็นต้องมีบัญชีมาก่อน คำเชิญพาเขาสมัครให้เอง |
| `src/pages/clusterAdmin/InvitationsTable.tsx` | `accepted` ตอนนี้อาจหมายถึง "สมัครและเข้าร่วมพร้อมกัน" — ตรวจข้อความและ tooltip ให้ไม่ขัด ส่วน `statusVariant` และเงื่อนไข resend/revoke ไม่ต้องแก้ |
| `src/pages/platformConfig/InvitationConfigCard.tsx` | ตรวจว่าไม่มีข้อความที่บอกว่าผู้รับต้องสมัครก่อน |
| `src/services/clusterAdminService.ts` | ไม่ต้องแก้ — endpoint ฝั่ง Admin เหมือนเดิมทั้งหมด |

## สิ่งที่ backend ต้องส่งมาก่อน

`GET /api/invitations/:token` เพิ่มสองฟิลด์ที่หน้าจอนี้พึ่งพา — `requires_signup: boolean` และ
`email_masked: string` **deploy backend ก่อน platform เสมอ** ไม่งั้นหน้ารับคำเชิญตัดสินใจไม่ได้ว่า
จะแสดงฟอร์มสมัครหรือปุ่มเข้าสู่ระบบ
