# carmen-platform perpage ≤ 100 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** carmen-platform ไม่ส่ง `perpage=-1` หรือ `perpage>100` อีกเลย (31 จุด) โดยไม่ตัดข้อมูลทิ้งเงียบ ๆ

**Architecture:** ทุกจุดที่ต้องการทั้งชุดไล่ทีละหน้าด้วย `fetchAllPages` (`src/utils/fetchAllPages.ts`, หน้าละ 100, ≤10 หน้า) · BU ใช้ของกลางใหม่ `fetchAllBusinessUnits` · cluster ใช้ `fetchAllClusters` ที่มีอยู่

**Tech Stack:** Vite + React 19 + TypeScript, vitest, bun

**Spec:** `docs/superpowers/specs/2026-09-30-perpage-cap-100-design.md`

## Global Constraints

- Branch `feature/perpage-cap-100` (มี commit spec อยู่แล้ว) · commit message ภาษาไทย
- **ห้ามสร้างไฟล์เทสต์ใหม่** และข้ามขั้น "เขียนเทสต์ที่ fail" ทุกขั้น — แต่เทสต์เดิมที่พังเพราะงานนี้ต้องแก้ให้ผ่าน **โดยไม่ลบ assertion** (แก้ค่าที่คาด / รูป mock ให้ตรงของใหม่)
- mock ใน test ที่คืน envelope ต้องมี `paginate.total` (หรือหน้าถัดไปคืน `data: []`) ไม่งั้น `fetchAllPages` จะไล่ถึง 10 หน้า
- `fetchAllPages` / `fetchAllBusinessUnits` / `fetchAllClusters` คืน **array** — ลบการ unwrap `data.data || data` ที่จุดนั้นทิ้ง
- import เป็น relative path ตามความลึกของไฟล์ (รีโปนี้ไม่มี alias `@/`) เช่น `src/pages/X.tsx` → `'../utils/fetchAllPages'`, `src/pages/a/X.tsx` → `'../../utils/fetchAllPages'`, `src/pages/a/b/X.tsx` → `'../../../utils/fetchAllPages'`
- ถ้า type ของ response service ไม่เข้ากับ `PagedResponse<T>` ตรง ๆ ให้ระบุ generic `fetchAllPages<Role>(...)` และ cast ผลของ service เป็น `PagedResponse<Role>` — ห้ามใช้ `any`
- ทุก task จบด้วย `bun run typecheck` · `bun run lint` (0 error) · `bun run test` ผ่านทั้งชุด

```ts
import businessUnitService from '../services/businessUnitService';
import { fetchAllPages, type PagedResponse } from './fetchAllPages';
import type { BusinessUnit } from '../types';

export interface FetchAllBusinessUnitsOptions {
  /** กรองด้วย cluster_id ฝั่ง server (advance where) */
  clusterId?: string;
  /** เช่น 'code:asc' — ไม่ส่ง = ลำดับของ backend */
  sort?: string;
  /** ชื่อใน devLog เมื่อชนเพดาน */
  label: string;
}

/**
 * BU ทั้งหมด (หรือทั้งหมดของ cluster หนึ่ง) แบบไล่ทีละหน้า — ทางแทน `perpage: -1` / `perpage: 200`
 * ที่ gateway จะตอบ 400 (ช่วง 4c ของ lazy-lookup) · หน้าละ 100 สูงสุด 10 หน้า ชนเพดาน = devLog
 */
export function fetchAllBusinessUnits({
  clusterId, sort, label,
}: FetchAllBusinessUnitsOptions): Promise<BusinessUnit[]> {
  const advance = clusterId ? JSON.stringify({ where: { cluster_id: clusterId } }) : undefined;
  return fetchAllPages<BusinessUnit>(
    (page, perpage) =>
      businessUnitService.getAll({
        page,
        perpage,
        ...(sort ? { sort } : {}),
        ...(advance ? { advance } : {}),
      }) as Promise<PagedResponse<BusinessUnit>>,
    { pageSize: 100, maxPages: 10, label, context: clusterId ? { clusterId } : undefined },
  );
}
```

(ถ้า `import type { BusinessUnit }` อยู่คนละที่ ให้ใช้ที่เดียวกับ `SubscriptionForm.tsx`)
